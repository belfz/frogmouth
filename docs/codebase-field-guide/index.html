Learn Frogmouth as a system,
not a pile of Swift.

Frogmouth is a native macOS editor whose saved project is a list of decisions. Swift owns the experience and the editing model; AVFoundation previews those decisions; FFmpeg turns them into durable media.

01

The project is decisions

.frogmouth JSON stores sources, ordered clips, trim ranges, stabilization effects, fades, and timeline format. It never embeds or mutates source media.

02

Edits are commands

Every durable timeline mutation passes through ProjectCommand and ProjectEditor, so validation, undo/redo, and autosave agree.

03

Heavy work is replaceable

Protocols isolate inspection, file writing, thumbnail generation, and FFmpeg execution. Actors serialize disk state; fakes make the difficult paths testable.

The useful architectural label

“MVVM-ish” is true but incomplete. A better description is command-driven domain core + actor-isolated services + a main-actor application coordinator + declarative SwiftUI views.

Chapter 04 · The source of truth

A small model with
strong invariants.

The durable state is deliberately boring: Codable value types with stable IDs and rational time. Complexity lives in validation and transformations, not hidden object graphs.

Root

ProjectState

schemaVersion, ID, name, media library, optional timeline format, ordered clips.

Source

MediaAsset

Path reference + fingerprint + inspected facts. One source can back many timeline clips.

Decision

TimelineClip

Asset ID, source range, ordered stabilization passes, optional picture-only fades.

Precision

MediaTime · MediaTimeRange · FrameRate

Exact rationals and checked arithmetic. Frames are mapped; seconds are for display and FFmpeg boundaries.

The command gate

One path for durable edits

View gesture
  → ProjectCommand
  → ProjectEditor.apply(_:)
  → validate complete ProjectState
  → ProjectHistory records snapshot
  → ProjectDocumentSession schedules autosave
  → ViewModel publishes one coherent snapshot

Imports, insertion, split, trim, duplicate, move, delete, stabilization, and fades all use this path. Undo/redo restores validated project snapshots rather than attempting inverse media operations.

The exception that proves it

Trim is a transaction

Pointer movement needs live feedback without adding hundreds of undo entries. A TrimTransaction keeps a pending range; commit emits one durable command; cancel restores the original.

Cache identity

Generated, validated, disposable

SHA-256 keys include source fingerprint, processing revision, FFmpeg tool revision, and ordered parameters. A manifest records the artifact filename and byte count. Any mismatch becomes a typed stale reason.

identity → sorted JSON → SHA-256 key
         ↘ artifact + manifest.json
change source / tool / algorithm / params
         → stale → regenerate
Important invariant

Never trust an output because FFmpeg exited 0

TimelineExporter writes to a unique partial file, reinspects it, validates the media facts and provenance, checks cancellation again, then finalizes atomically.

This is why failures should retain actionable diagnostics but not leave a plausible-looking final file.

Chapter 07 · House style

Value semantics first.
Isolation at the edges.

The code favors explicit types and compiler-enforced concurrency over frameworks or clever abstraction. Most dependencies are plain initializers with protocol-typed defaults.

Value model

Structs carry state

public struct TimelineClip:
  Codable, Equatable,
  Identifiable, Sendable

Codable persists it, Equatable enables snapshots/tests, Sendable permits actor crossings.

Typed failures

Errors explain recovery

public enum TimelineEditError:
  LocalizedError,
  Equatable, Sendable

Cases are assertable in tests; descriptions are directly useful in the UI and diagnostics.

Dependency seam

Protocols at I/O boundaries

private let runner:
  any FFmpegExecuting

Production gets a real process runner; tests inject recording, failing, or cancelling fakes.

Chapter 10 · Human + AI operating manual

Know where to cut.
Know what must remain true.

You do not need to type every line to own the system. Your leverage is choosing the behavior, recognizing the boundary, demanding the right evidence, and reviewing invariants rather than syntax alone.

01

Sources stay untouched

All edits are decisions; generated outputs go to cache, workspace, or an explicit export destination.

02

Frames stay exact

Use MediaTime, FrameRate, and mapping helpers. Do not make editing decisions with floating-point seconds.

03

Durable edits use commands

Do not mutate published project state from a view or bypass history/session validation.

04

Schema changes are explicit

Update schema version, codec/migration behavior, canonical fixture, compatibility test, design docs, and changelog.

05

Cache validity is explainable

New processing behavior changes its identity/revision; stale results are regenerated rather than silently reused.

06

Outputs are inspected

A successful process exit is not sufficient. Validate before atomically publishing the file.

Review the AI at the right altitude

Six questions beat a line-by-line syntax audit

  1. 1

    Which durable model changed? If none, why does persistence code move?

  2. 2

    Which invariant enforces the behavior? Look for one central validation point.

  3. 3

    What is the cancellation/failure story? Partial cache or export files must not become truth.

  4. 4

    What crosses the main actor? Heavy inspection, file I/O, composition, and processes should not block UI state.

  5. 5

    Which test layer proves it? Pure logic first; fixture-backed evidence when media behavior changes.

  6. 6

    Which compatibility number or document changes? Schema, cache, processing, FFmpeg, app version, changelog.
